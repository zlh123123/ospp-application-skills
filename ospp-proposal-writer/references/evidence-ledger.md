# Evidence Ledger

Maintain this ledger while drafting. It may remain internal unless the user requests it, but the final fact-check summary should expose unresolved claims.

| Claim | Source | Evidence status | Safe wording | Action needed |
| --- | --- | --- | --- | --- |
| Existing repository behavior | file link and revision | verified/partial/inferred/blocked | exact bounded statement | test or inspection |
| Build or test result | command, environment, and output | verified/blocked | observed result only | resolve blocker if material |
| Applicant experience | resume, portfolio, or user statement | verified/user-provided | do not inflate proficiency | request evidence only if decisive |
| Prior contribution | public PR, issue, or commit | verified | describe actual role and status | none or verify merge state |
| Proposed design | repository audit and rationale | inferred | label as planned work | mentor confirmation if boundary is unclear |
| Dataset or benchmark | repository or official source | verified/partial/blocked | state availability and version | confirm access or construct alternative |
| Mentor preference | supplied correspondence | user-provided/verified | quote or paraphrase narrowly | do not generalize |

Do not include a claim in the application when its safest wording would still mislead a mentor. Replace it with a bounded statement or leave it as an external question.
