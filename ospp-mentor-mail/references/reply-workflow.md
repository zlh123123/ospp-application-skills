# Reply Workflow

Before drafting a reply, make a private response map:

| Mentor message item | Type | Applicant response | Evidence or action |
| --- | --- | --- | --- |
| Direct question | answer required | concise answer | resume, repo result, or user fact |
| Requested change | acknowledge and act | completed/planned/needs clarification | exact artifact or next step |
| Technical constraint | update plan | effect on design or schedule | repository investigation |
| Resource offer | acknowledge | how it will be used | do not imply access before granted |
| Ambiguity | clarify | one focused question | explain why it changes the plan |

Then draft the email:

1. acknowledge the reply without ceremonial thanks;
2. answer the mentor's questions in their order;
3. state completed revisions or the next concrete action;
4. ask only remaining material questions;
5. close briefly.

After the email, report any changes that should be passed to other skills:

- official or mentor-confirmed requirement changes;
- repository, branch, dataset, model, benchmark, or infrastructure details;
- proposal sections that must be revised;
- deadlines or requested preliminary contributions.

Do not treat a mentor suggestion as a completed applicant action. Do not interpret a polite reply as selection.
